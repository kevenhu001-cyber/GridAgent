# Bounded AC parallel execution and verified local cache

Only newly registered fixed-IR AC tasks use the new batch scheduler. GRIDAGENT_AC_WORKERS defaults to 1 and accepts 1–4. A single coordinator commits the contiguous batch's reservations before launch, starts isolated native subprocesses through a bounded thread pool, joins them before releasing the execution lock, and settles results in frozen scenario order. Workers never mutate the task database. Native subprocesses keep their existing single-thread BLAS settings. Cancellation stops dispatch at cooperative boundaries; active native calls are polled and killed by the existing backend. A reserved but unlaunched or interrupted run is not silently retried. The cap is per task, not a global CPU or hard memory quota.

GRIDAGENT_VERIFIED_CACHE=1 opts in to local reuse for fixed AC tasks using the actual native solver. The default is off. A cache key includes model and native request content, acceptance limits, evaluator, Python/platform, installed package versions, backend version, worker/evaluator source hashes and fixed solver settings. Unavailable identity disables caching. Entries are bounded to 512 references; they do not delete original run artifacts. On lookup, the source evidence hashes, native request and result identity, solver version and current independent verifier must agree. Verified files are copied and rehashed in a staging directory, the new run ID and source ID recorded, and the directory published atomically. The ordinary result verifier then runs again on the copied evidence. Cached results consume planned run slots; reports separately expose cache_hits and native_launches_observed. The latter is an observed count, not a guarantee about uncertain interrupted runs.

The cache covers only the allowlisted AC verification artifacts, not auxiliary native tables, network.json, solver logs or a full native project export. It does not assert cryptographic authenticity or byte-identical environments; package versions/source hashes are conservative environment identifiers. Dispatch and arbitrary repair workflows remain uncached and serial. No measured speedup, global resource scheduler, memory quota or cross-machine cache is claimed. Integration tests exercise a real two-scenario native solve and subsequent cache reuse; CI must verify them.
