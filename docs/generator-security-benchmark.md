# Generator contingency and optimization acceptance benchmark

The optional network.security contract now accepts outage_units in addition to outage_lines, one to eight single-component cases total. Each listed unit is tripped independently at each hour (even if already offline). Its corrective output is fixed to zero and its allocated reserve is unavailable; its original commitment/minimum-output and downward ramp do not constrain the forced outage. All surviving units retain the previous online state and output bounds, upward allocated reserve and response-time downward ramp. The network remains intact in a unit outage; line outages retain their previous behavior. Storage, demand and base schedule are fixed across cases; each case is independent, no simultaneous or sequential contingencies. The objective still minimizes base schedule cost only.

Compiler identity dc-component-security-commitment-milp-v1 is used when any unit outage is requested. The existing line-only compiler, canonical hashes, variable/row ordering and report shape remain unchanged. The independent physical verifier checks failed unit output, surviving reserve and power limits, DC flow and nodal balance. Unit cases use a separate unit_cases map and explicit coverage flag. A failed unit's allocated base reserve is reported separately from usable reserve. A feasible schedule does not establish a remaining reserve requirement after the outage, frequency response, dynamic stability or AC feasibility. The AC checker still supports only selected base/line-outage snapshots; its full DC coverage flag is false when any generator contingency exists.

Run `python -m gridagent.optimization_benchmark --repeats 3` for a small synthetic acceptance benchmark. Six fixed cases cover LP dispatch, polynomial NLP dispatch and DC base, line, unit and mixed security. Each records input digest, problem dimensions, solver status, independent primal verification, analytic objective reference, solve and verification wall times, and Python/platform/SciPy versions. Exit status is nonzero if any reference or feasibility check fails. Times include in-process compilation/solve and verification overhead, not application startup or native AC runs. No time threshold, speedup, IEEE benchmark or scale claim. Repeat counts 1..5. Results must be measured on the target system; these references are analytic, not pre-measured data.

For the two-bus benchmark, 6 MW demand and 4 MW transmission limit imply 4 MW cheap generation at 10 CNY/MWh plus 2 MW local at 50 CNY/MWh (140 CNY). The loss of cheap generation requires the local unit to supply 6 MW. With a 2 MW response limit, base local generation must be at least 4 MW; the security-constrained reference is 220 CNY. The line outage has the same reference under these parameters. This is a minimal synthetic regression case, not an IEEE system.
