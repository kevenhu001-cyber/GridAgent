# AC/DC schedule cross-check

Start with a completed independently verified network unit_commitment mathematical study. Use --ac-check FILE.json or --ac-check-resume ID (equivalent slash commands). ACCheckSpec binds the source study ID, independent reviewed ModelIR, exact unit/storage device mappings, one explicitly mapped slack unit at the DC reference bus, per-unit reactive limits, explicit hourly reactive demand at every bus, selected hour/outage snapshots, AC acceptance limits and permitted slack active-power deviation. It requires exactly matching bus IDs and line IDs/orientation, one load per bus, no unaccounted equipment and matching DC coefficient V_kV^2 / X_ohm. Storage energy ratings must match. No inferred AC resistance, capacitance, voltage, reactive capability or thermal current limit.

The compiler freezes each snapshot with the scheduled online generator P (offline units removed), scheduled net storage consumption and starting SOC, bus active/reactive demand and the authorized voltage setpoints/line impedances. Connected selected DC line outages are supported; islanded AC cases and offline slack units are explicitly rejected rather than guessed. No transformers or extra equipment in this first mapping. A slack source represents a real mapped thermal unit, not unlimited external supply. Each snapshot reserves a unique native run before invoking the pandapower worker with a per-run timeout; previous reservations are recovered without relaunch. Up to 24 snapshots, no cache. The study freezes the original DC report hash and all native request fingerprints, and rechecks committed results/artifact hashes on resume.

The existing independent AC evaluation checks voltage, loading, connectivity and power balance. Supplementary native device-result tables are independently hashed and checked for active dispatch, reactive limits, slack deviation and actual thermal generation capacity. For outage cases, actual generation must also remain within the DC allocated upward reserve and downward response ramp. Fixed load/storage P/Q, both-end active line limits, passive losses and generation/demand/loss reconciliation are checked. No Q-limit-enforcing redispatch: a Q-limit violation rejects the candidate rather than silently changing it. AC feasibility is distinct from DC feasibility. The report states selected snapshot coverage, failures and evidence, not a general AC-OPF result or dynamic/security certificate. Base case slack loss compensation may consume spare capacity; this does not certify remaining spinning reserve. Unsupported cases require a separate AC model and workflow.

Tests cover strict input mapping, outage authorization, interrupted reservations, no execution of pending source study and a native integration case with reactive rejection. Prior security test fixture now declares the unit_commitment family explicitly; no router fallback or weakened validation.
